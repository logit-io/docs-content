Install the OpenTelemetry Collector Contrib package and export logs, traces and metrics to Hosted OpenTelemetry with one `otlphttp/logit` exporter.

Applications that send OTLP themselves should use the language guide on [Getting started with OpenTelemetry](../getting-started/opentelemetry/) and should not install the Collector.

## Endpoint

- Endpoint: `https://@logs_id-otel.logit.io` (no port on the Logit host)
- Exporter: `otlphttp/logit` (OTLP over HTTP)
- Username: `@logs_id-otel`
- Password: the API key on the Hosted OpenTelemetry card (Settings, Endpoints). Replace `<your-api-key>`. Do not commit that key.

`@logs_id` is your logs stack id. Do not export with gRPC to this host, and do not add a port to the endpoint. A local `otlp` receiver on `127.0.0.1` is only for apps on that machine. It is not the Logit address.

The samples pin **otelcol-contrib 0.161.0**.

<Steps>
  ## Install

  ### Debian or Ubuntu

  The package registers the `otelcol-contrib` systemd service, which reads `/etc/otelcol-contrib/config.yaml` and runs as the `otelcol-contrib` user. Adding that user to `adm` lets it read `/var/log/syslog`.

  ```bash copy
  curl -fsSLO https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.161.0/otelcol-contrib_0.161.0_linux_amd64.deb
  sudo dpkg -i otelcol-contrib_0.161.0_linux_amd64.deb
  sudo usermod -aG adm otelcol-contrib
  ```

  ### RHEL or Amazon Linux

  ```bash copy
  curl -fsSLO https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.161.0/otelcol-contrib_0.161.0_linux_amd64.rpm
  sudo rpm -ivh otelcol-contrib_0.161.0_linux_amd64.rpm
  ```

  ### Windows

  Run this from an elevated PowerShell. The MSI installs to `C:\Program Files\OpenTelemetry Collector` and registers the `otelcol-contrib` service with that folder's `config.yaml`. The service starts on install because the MSI ships a default config. Replace that file before you rely on it.

  ```powershell copy
  Invoke-WebRequest -Uri https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.161.0/otelcol-contrib_0.161.0_windows_x64.msi -OutFile otelcol-contrib_0.161.0_windows_x64.msi
  Start-Process msiexec.exe -ArgumentList "/i otelcol-contrib_0.161.0_windows_x64.msi /qn" -Wait
  ```

  ## Servers and log files

  Save this as `/etc/otelcol-contrib/config.yaml` on Linux. It tails `/var/log/syslog` and `/var/log/messages`, receives local OTLP, scrapes host metrics, and exports logs, traces and metrics. The Collector user needs read access to each file you add under `filelog` `include`.

  ```yaml copy /@logs_id/
  extensions:
    basicauth/logit:
      client_auth:
        username: "@logs_id-otel"
        password: "<your-api-key>"

  receivers:
    filelog:
      include: ["/var/log/syslog", "/var/log/messages"]
      start_at: end
    otlp:
      protocols:
        http: { endpoint: "127.0.0.1:4318" }
        grpc: { endpoint: "127.0.0.1:4317" }
    hostmetrics:
      collection_interval: 30s
      scrapers: { cpu: {}, memory: {}, disk: {}, filesystem: {}, network: {}, load: {} }

  processors:
    resourcedetection:
      detectors: [system]
    resource/logit:
      attributes:
        - { key: service.name, value: "my-server", action: insert }
    batch: {}

  exporters:
    otlphttp/logit:
      endpoint: "https://@logs_id-otel.logit.io"
      auth: { authenticator: basicauth/logit }

  service:
    extensions: [basicauth/logit]
    pipelines:
      logs:
        receivers: [filelog, otlp]
        processors: [resourcedetection, resource/logit, batch]
        exporters: [otlphttp/logit]
      traces:
        receivers: [otlp]
        processors: [resourcedetection, batch]
        exporters: [otlphttp/logit]
      metrics:
        receivers: [hostmetrics, otlp]
        processors: [resourcedetection, resource/logit, batch]
        exporters: [otlphttp/logit]
  ```

  On Windows, save the config as `C:\Program Files\OpenTelemetry Collector\config.yaml`. It reads the Application, System and Security event logs instead of files. The service runs as LocalSystem, so the Security log is readable.

  ```yaml copy /@logs_id/
  extensions:
    basicauth/logit:
      client_auth:
        username: "@logs_id-otel"
        password: "<your-api-key>"

  receivers:
    windowseventlog/application:
      channel: application
      start_at: end
    windowseventlog/system:
      channel: system
      start_at: end
    windowseventlog/security:
      channel: security
      start_at: end
    otlp:
      protocols:
        http: { endpoint: "127.0.0.1:4318" }
        grpc: { endpoint: "127.0.0.1:4317" }
    hostmetrics:
      collection_interval: 30s
      scrapers: { cpu: {}, memory: {}, disk: {}, filesystem: {}, network: {}, load: {} }

  processors:
    resourcedetection:
      detectors: [system]
    resource/logit:
      attributes:
        - { key: service.name, value: "my-server", action: insert }
    batch: {}

  exporters:
    otlphttp/logit:
      endpoint: "https://@logs_id-otel.logit.io"
      auth: { authenticator: basicauth/logit }

  service:
    extensions: [basicauth/logit]
    pipelines:
      logs:
        receivers: [windowseventlog/application, windowseventlog/system, windowseventlog/security, otlp]
        processors: [resourcedetection, resource/logit, batch]
        exporters: [otlphttp/logit]
      traces:
        receivers: [otlp]
        processors: [resourcedetection, batch]
        exporters: [otlphttp/logit]
      metrics:
        receivers: [hostmetrics, otlp]
        processors: [resourcedetection, resource/logit, batch]
        exporters: [otlphttp/logit]
  ```

  ## Host metrics

  Use the same install as above, then this config. It sends CPU, memory, disk, filesystem, network and load metrics. On Windows the same scrapers apply (`load` is emulated).

  ```yaml copy /@logs_id/
  extensions:
    basicauth/logit:
      client_auth:
        username: "@logs_id-otel"
        password: "<your-api-key>"

  receivers:
    hostmetrics:
      collection_interval: 30s
      scrapers: { cpu: {}, memory: {}, disk: {}, filesystem: {}, network: {}, load: {} }

  processors:
    resourcedetection:
      detectors: [system]
    resource/logit:
      attributes:
        - { key: service.name, value: "my-server", action: insert }
    batch: {}

  exporters:
    otlphttp/logit:
      endpoint: "https://@logs_id-otel.logit.io"
      auth: { authenticator: basicauth/logit }

  service:
    extensions: [basicauth/logit]
    pipelines:
      metrics:
        receivers: [hostmetrics]
        processors: [resourcedetection, resource/logit, batch]
        exporters: [otlphttp/logit]
  ```

  ## Restart

  Linux, after you save `/etc/otelcol-contrib/config.yaml`:

  ```bash copy
  sudo systemctl restart otelcol-contrib
  sudo journalctl -u otelcol-contrib -n 20 --no-pager
  ```

  Windows, after you save `C:\Program Files\OpenTelemetry Collector\config.yaml`. The service logs to the Application event log under the `otelcol-contrib` source.

  ```powershell copy
  Restart-Service otelcol-contrib
  Get-WinEvent -FilterHashtable @{ LogName = 'Application'; ProviderName = 'otelcol-contrib' } -MaxEvents 20 | Format-List TimeCreated, Message
  ```

  ## Kubernetes

  One Helm install. The chart presets mount pod logs and host metrics. The image tag is `0.161.0`. `basicauth/logit` stays next to the chart's `health_check` extension, which its probes need. Logs, traces and metrics all export with `otlphttp/logit`.

  ```bash copy /@logs_id/
  helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts && \
  helm upgrade --install otel-logit open-telemetry/opentelemetry-collector \
    --set mode=daemonset \
    --set image.repository=otel/opentelemetry-collector-contrib \
    --set image.tag=0.161.0 \
    --set presets.logsCollection.enabled=true \
    --set presets.hostMetrics.enabled=true \
    --set config.extensions.basicauth/logit.client_auth.username=@logs_id-otel \
    --set config.extensions.basicauth/logit.client_auth.password=<your-api-key> \
    --set config.exporters.otlphttp/logit.endpoint=https://@logs_id-otel.logit.io \
    --set config.exporters.otlphttp/logit.auth.authenticator=basicauth/logit \
    --set 'config.service.extensions={health_check,basicauth/logit}' \
    --set 'config.service.pipelines.logs.exporters={otlphttp/logit}' \
    --set 'config.service.pipelines.traces.exporters={otlphttp/logit}' \
    --set 'config.service.pipelines.metrics.exporters={otlphttp/logit}'
  ```

  ## Existing Collector

  If `otelcol-contrib` is already installed, do not install the deb, rpm or MSI again. Merge this extension and exporter into the config you already run, add `basicauth/logit` to `service.extensions`, and set `otlphttp/logit` as the exporter on your logs, traces and metrics pipelines. This fragment has no `service.pipelines` block, so it does not drop receivers you already defined.

  ```yaml copy /@logs_id/
  extensions:
    basicauth/logit:
      client_auth:
        username: "@logs_id-otel"
        password: "<your-api-key>"

  exporters:
    otlphttp/logit:
      endpoint: "https://@logs_id-otel.logit.io"
      auth: { authenticator: basicauth/logit }
  ```

  Restart with the same commands as above.
