### Configure Lambda function

From your Amazon Console browse to the <a target="_blank" href="https://console.aws.amazon.com/lambda/home">Lambda functions</a> and choose Create Function.

Choose **Author from scratch**, enter a name, select a current Node.js runtime, then choose **Create function**.

![Create function by selecting Author from scratch](@/images/integrations/aws-cloudwatch/aws-lambda-function-small.png)

Replace the contents of `index.mjs` with the following handler. Keep the Lambda handler setting as `index.handler`.

```js copy showLineNumbers
import { gunzipSync } from "node:zlib";

export async function handler(input) {
  const compressed = Buffer.from(input.awslogs.data, "base64");
  const payload = JSON.parse(gunzipSync(compressed).toString("utf8"));
  if (payload.messageType === "CONTROL_MESSAGE") return;

  const apiKey = process.env.LOGIT_API_KEY;
  if (!apiKey) throw new Error("Set LOGIT_API_KEY");

  const maxBodyBytes = 9_800_000;
  let offset = 0;
  while (offset < payload.logEvents.length) {
    const batch = [];
    let batchBytes = 2; // Opening and closing brackets.
    while (offset < payload.logEvents.length && batch.length < 1_000) {
      const logEvent = payload.logEvents[offset];
      const event = JSON.stringify({
        message: logEvent.message,
        logGroupName: payload.logGroup,
        logStreamName: payload.logStream,
        timestamp: new Date(logEvent.timestamp).toISOString(),
      });
      const eventBytes = Buffer.byteLength(event, "utf8");
      if (eventBytes + 2 > maxBodyBytes) {
        console.error(
          "A CloudWatch log event exceeds the 9,800,000-byte limit for a JSON array request.",
        );
        return;
      }
      const bytesToAdd = eventBytes + (batch.length === 0 ? 0 : 1); // Include the comma.
      if (batchBytes + bytesToAdd > maxBodyBytes) break;

      batch.push(event);
      batchBytes += bytesToAdd;
      offset++;
    }

    const response = await fetch("https://@logitApiEndpoint/v2", {
      method: "POST",
      headers: {
        ApiKey: apiKey,
        "Content-Type": "application/json",
        LogType: "cloudwatch_lambda",
      },
      body: `[${batch.join(",")}]`,
      signal: AbortSignal.timeout(10_000),
      redirect: "error",
    });
    const details = await response.text().catch(() => "");
    if (response.status === 202) continue;
    if (response.status === 429 || response.status >= 500) {
      throw new Error(`Logit.io returned HTTP ${response.status}`);
    }
    if (response.status === 403) {
      console.error(
        "Logit.io returned HTTP 403. Remove the forwarder or update LOGIT_API_KEY with an active stack's API key.",
      );
    } else {
      console.error(
        `Logit.io returned HTTP ${response.status}. Fix the request before sending it again.`,
        details,
      );
    }
    return;
  }
}
```

For high volumes, send JSON arrays or NDJSON to `/v2`. The handler posts JSON arrays with 1 to 1,000 events per request. The raw request body and each serialised event are capped at 9,800,000 bytes. Use `application/json` for a JSON object or array, and `application/x-ndjson`, `application/ndjson` or `application/jsonl` for NDJSON. HTTP 202 means the API queued all events. Each event becomes a separate log.

The handler logs HTTP 400 (invalid body), HTTP 403 (disabled or unmapped key) and HTTP 413 (event count or byte limit exceeded), then stops forwarding the payload without triggering a Lambda retry. Invalid bodies include malformed JSON, invalid NDJSON lines, non-object events, empty batches, and non-standard numbers such as `NaN`, `Infinity` or `-Infinity`. For HTTP 403, remove the forwarder or update it with an active stack's API key.

The API returns HTTP 503 with `Retry-After: 5` (seconds) for temporary failures. HTTP 429, HTTP 5xx, connection errors and timeouts fail the invocation so Lambda can retry. A retry can resend events that already reached the queue. Set the function timeout to allow enough time to forward a full CloudWatch payload. [AWS Lambda retry behaviour](https://docs.aws.amazon.com/lambda/latest/dg/invocation-async-error-handling.html)

### Environment variables

In the Lambda function's environment variables, set `LOGIT_API_KEY` to `@apikey`. You can also find the API key in **Stack > Settings > Stack API Keys**.

Save and deploy the function.

### Configure CloudWatch trigger

From the Lambda designer choose to Add Trigger and select the required CloudWatch Log Group.

![Add trigger in Designer](@/images/integrations/aws-cloudwatch/aws-lambda-trigger.png)

New log events in the selected log group are forwarded to your stack.
