# Getting started with OpenTelemetry

Send logs, traces and metrics from your application to Logit.io Hosted OpenTelemetry. One endpoint and one credential cover all three signals.

This page is the setup for an application process. It does not install the OpenTelemetry Collector. Servers, host metrics, Kubernetes and an existing Collector use the [OpenTelemetry Collector](../integrations/otel-collector/) guide.

## Endpoint

- Endpoint: `https://@logs_id-otel.logit.io` (no port)
- Protocol: `http/protobuf`
- Username: `@logs_id-otel`
- API key: the key on the Hosted OpenTelemetry card (Settings, Endpoints). Replace `<your-api-key>` in the samples. Do not commit that key.
- Header: `Authorization=Basic%20` plus the Base64 of `username:api-key`. The space after `Basic` is percent-encoded. Do not send `Authorization=Basic ` with a raw space as the header value.

`@logs_id` is your logs stack id. Signed-in docs fill it in. Do not add a port, and do not use gRPC to this host.

Set the variables on the process that runs the app (launch settings, container environment, IIS `environmentVariables`, systemd, or a Windows service). An export in the current terminal only applies to a local run in that same window.

<Tabs items={["Linux and macOS", "Windows PowerShell"]}>
<Tab>

```bash copy /@logs_id/
export OTEL_SERVICE_NAME="my-service"
export OTEL_EXPORTER_OTLP_ENDPOINT="https://@logs_id-otel.logit.io"
export OTEL_EXPORTER_OTLP_PROTOCOL="http/protobuf"
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Basic%20$(printf '%s:%s' '@logs_id-otel' '<your-api-key>' | base64 | tr -d '\n')"
```

</Tab>
<Tab>

```powershell copy /@logs_id/
$env:OTEL_SERVICE_NAME = "my-service"
$env:OTEL_EXPORTER_OTLP_ENDPOINT = "https://@logs_id-otel.logit.io"
$env:OTEL_EXPORTER_OTLP_PROTOCOL = "http/protobuf"
$pair = "@logs_id-otel:<your-api-key>"
$env:OTEL_EXPORTER_OTLP_HEADERS = "Authorization=Basic%20" + [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($pair))
```

</Tab>
</Tabs>

## Language registration

Use the same environment variables on every language. Package names below are the ones the dashboard onboarding prompt uses. Do not set the bare host as `Endpoint` in code.

- [.NET](../integrations/dotnet/) — `UseOtlpExporter()` plus the .NET profiler when you want zero-code
- [Python](../integrations/python/) — `opentelemetry-instrument`
- [Node.js](../integrations/nodejs/) — `node --require @opentelemetry/auto-instrumentations-node/register`
- [Java](../integrations/java/) — `opentelemetry-javaagent.jar`
- [Go](../integrations/go/) — `autoexport` with the HTTP exporters
- [Ruby](../integrations/ruby/)
- [PHP](../integrations/php/)
- [Elixir](../integrations/elixir/)
- [Erlang](../integrations/erlang/)
- [C++](../integrations/cpp/), [Rust](../integrations/rust/) and [Swift](../integrations/swift/) — environment variables on this page, then the language registration. Those pages do not name a package.

If your language is not in that list, keep the environment variables above and follow that language's OpenTelemetry registration. Do not invent package names, do not install `otelcol-contrib` for this path, and do not use gRPC to the Logit host.
