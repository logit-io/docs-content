# OpenSearch API (user credentials)

Call the OpenSearch REST API with **named user or service-account credentials** at `https://{stack-id}-es-user.logit.io`. Permissions follow your [Teams and custom OpenSearch roles](/account-administration/account-access-users-teams/roles-access/managing-opensearch-grafana-security-roles), the same roles that apply in OpenSearch Dashboards.

The same Basic login works for **Personal MCP** at `https://{stack-id}-mcp-user.logit.io/mcp` when enabled on a Small Team, Business or Custom stack. Individual and legacy Development plans use the stack MCP endpoint only.

Legacy stack API key access on `{stack-id}-es.logit.io` is **unchanged**. Use that endpoint when you need full programmatic access with the stack key. Use `-es-user` when you want requests scoped to a person or CI identity.

<Callout type="warning">
**Different credentials from `-es`.** The `-es-user` endpoint does **not** accept your stack API key or Basic auth with stack ID + stack key. Use the OpenSearch API username and password from **Profile settings** (humans) or **Account Settings → service accounts** (CI). Those values are separate from `@opensearch.username` / `@opensearch.password` / `@opensearch.apiKey`.
</Callout>

<Callout type="info">
OpenSearch API user credentials are available on **all plans** and the 14-day free trial. The stack must use the OpenSearch HTTP API.
</Callout>

<Callout type="info">
When signed in, examples auto-fill `@esUser.*` when the feature is enabled on your selected stack and you have opted in from Profile (or when viewing service-account docs).
</Callout>

### Choose this endpoint when

| Use case | Endpoint |
| --- | --- |
| Full stack API access (ingest, admin scripts, stack key) | `{stack-id}-es.logit.io` — [Connect to Your Cluster](/opensearch-api/connect) |
| Per-user or service-account access (Teams roles apply) | `{stack-id}-es-user.logit.io` — this guide |
| Read-only AI tooling with your own login (Small Team, Business, Custom) | `https://{stack-id}-mcp-user.logit.io/mcp` — [Personal MCP setup](/opensearch-api/hosted-mcp#2-connect-with-personal-mcp) |
| Read-only AI tooling with the shared stack credentials (all plans; credentials visible to stack administrators only) | `https://{stack-id}-mcp.logit.io/mcp` — [Hosted MCP quickstart](/opensearch-api/hosted-mcp) |

### Prerequisites

1. A Logit.io account on any plan or the 14-day free trial.
2. A Logs or OpenSearch stack with OpenSearch HTTP API available.
3. A stack administrator enables the feature on that stack.
4. For human access: the user has Teams access to the stack, then opts in from **Profile settings**.

### Enable on a stack (administrator)

1. Open the stack **Settings** page (Overview).
2. In **Access**, find **OpenSearch API (user credentials)**.
3. Select **Enable**.

Logit.io provisions the public hostname `{stack-id}-es-user.logit.io`. Legacy `{stack-id}-es.logit.io` continues to work with the stack API key.

Disable from the same **Access** card when you no longer need user-credential access on that stack. This also turns off **Personal MCP access** on the stack. Personal MCP requires both MCP and OpenSearch API user credentials to remain enabled; a stack administrator enables it separately. See the [Hosted MCP quickstart](/opensearch-api/hosted-mcp).

### Human users (Profile)

Each user creates their own Basic auth password from **Profile settings**:

1. Sign in and open **Profile settings**.
2. Under **OpenSearch API (user credentials)**, select **Enable OpenSearch API access** for the account.
3. Copy the username (your user ID) and password shown after opt-in.
4. Use those credentials against every stack where a stack administrator has enabled the feature and you have Teams access.

You can **rotate** or **disable** your personal credential from the same Profile section. Rotating invalidates the previous password immediately for both the REST API and Personal MCP. Update any clients using that login. Disabling removes access through both endpoints; OpenSearch Dashboards access is unchanged.

### Service accounts (CI / automation)

Account administrators manage service accounts under **Account Settings → OpenSearch API (user credentials)**:

1. Create a service account with a name and an OpenSearch role (for example `stack_user_ro`).
2. Optionally scope it to one enabled stack, or leave the scope empty for all stacks with the feature enabled.
3. Copy the username (`svc-{id}`) and password from the credentials block.
4. **Rotate password** or **Revoke** when credentials should change or be retired.

Service accounts are intended for CI, pipelines and agents that should not share a human user's password. The same service-account login works for Personal MCP, with its assigned role and stack scope. Rotating or revoking it affects both REST API and Personal MCP access.

### Connect with curl

Use the **OpenSearch API (user credentials)** username and password — not the stack `-es` credentials.

| Field | Humans (Profile) | Service accounts | Stack `-es` (do not use here) |
| --- | --- | --- | --- |
| **Username** | Your user ID (`@esUser.username`) | `svc-{id}` | Stack ID (`@opensearch.username`) |
| **Password** | Profile opt-in password (`@esUser.password`) | Service account password | Stack API key (`@opensearch.password` / `@opensearch.apiKey`) |
| **Host** | `@esUser.endpointAddress` | Same | `@opensearch.endpointAddress` |

```bash copy /@esUser.endpointAddress/ /@esUser.username/ /@esUser.password/
curl -u "@esUser.username:@esUser.password" \
  "@esUser.endpointAddress/_cluster/health?pretty"
```

Search example:

```bash copy /@esUser.endpointAddress/ /@esUser.username/ /@esUser.password/
curl -u "@esUser.username:@esUser.password" \
  -H "Content-Type: application/json" \
  "@esUser.endpointAddress/{index}/_search?pretty" \
  -d '{"query":{"match_all":{}},"size":10}'
```

Ports **443** and **9200** both use HTTPS, same as the stack `-es` endpoint.

### Compared with the stack API key (`-es`)

| | **Stack API key** (`-es`) | **User credentials** (`-es-user`) |
| --- | --- | --- |
| **Hostname** | `{stack-id}-es.logit.io` | `{stack-id}-es-user.logit.io` |
| **Auth** | API key query param or Basic (stack ID + stack key) | Basic (user ID or `svc-{id}` + password) |
| **Permissions** | Full programmatic access to the stack's data | Teams and custom roles for users; assigned role and scope for service accounts |
| **Who manages credentials** | Stack Endpoints / API keys | Profile (humans) or Account Settings (service accounts) |
| **Personal MCP login** | Not used for Personal MCP | Same user or service-account login on Small Team, Business and Custom |
| **Rotation / disable** | Managed separately from user credentials | Affects REST API and Personal MCP together |
| **Plan** | All plans with OpenSearch API | All plans with OpenSearch API |

### Troubleshooting

| Symptom | What to check |
| --- | --- |
| **401 Unauthorized** | Feature enabled on the stack? Profile opt-in complete (or service account created)? Username/password correct after a rotate? |
| **403 Forbidden** | Teams OpenSearch role may deny the operation (for example read-only users cannot index). Confirm roles under Account Settings → Teams. |
| **DNS / connection failed** | Feature may be disabled on the stack, or DNS/CNAME not ready yet — wait a minute and retry, or re-enable from **Access**. |
| **Works on `-es` but not `-es-user`** | Expected if you are using the stack API key on `-es`. Use Profile or service-account credentials on `-es-user`. |
