# Hosted OpenSearch MCP quickstart

Logit.io hosts a **read-only** [OpenSearch MCP server](https://github.com/opensearch-project/opensearch-mcp-server-py) for OpenSearch stacks and Logs stacks running an OpenSearch version. It is a standard MCP server, so you can connect any MCP-compatible AI client or model over HTTPS without running MCP locally. This guide uses **Cursor** and **Claude Desktop** as examples.

Personal MCP URL (Small Team, Business and Custom):

```text
https://{stack-id}-mcp-user.logit.io/mcp
```

Stack MCP URL (all plans):

```text copy /@mcp.endpointAddress/
@mcp.endpointAddress
```

Related product pages: [Hosted OpenSearch MCP](https://logit.io/platform/features/hosted-opensearch-mcp/), [Hosted OpenSearch](https://logit.io/platform/features/hosted-opensearch/).

<Callout type="info">
Included on **all plans** and in the [14-day free trial](https://dashboard.logit.io/sign-up) (no credit card required). Individual and legacy Development plans use the stack endpoint only. Logs stacks running Elasticsearch (ELK 6.8 or 7.x) cannot use Hosted MCP. Both MCP endpoints use **Basic authentication**.
</Callout>

<Callout type="info">
Stack administrators can see the shared stack MCP key in **Settings → Endpoints**. When signed in as an administrator with MCP enabled, the stack examples auto-fill `@mcp.endpointAddress`, `@mcp.username`, `@mcp.apiKey`, and `@mcp.base64encodedAuthString`. Other users connect through Personal MCP with credentials from **Profile settings**.
</Callout>

MCP is not a substitute for the full OpenSearch REST API. For programmatic write access or stack-key automation, use [Connect to Your Cluster](/opensearch-api/connect). For role-scoped human/CI API access, use [OpenSearch API (user credentials)](/opensearch-api/user-credentials).

### Prerequisites

1. A Logit.io account on any plan or the 14-day free trial.
2. An OpenSearch stack or a Logs stack running an OpenSearch version, with data you can search.
3. Permission to enable MCP on the stack (stack administrator or account owner/admin).
4. The stack in **Basic** authentication mode ([how to switch](/opensearch-api/connect#switching-authentication-mode)).
5. An AI client that supports remote MCP over HTTPS with custom headers (for example Cursor or Claude Desktop).

### 1. Enable on a stack

<Callout type="warning">
Your stack must be in **Basic** authentication mode before you enable Hosted MCP. See [Switching authentication mode](/opensearch-api/connect#switching-authentication-mode).
</Callout>

1. Sign in to the [Logit.io Dashboard](https://dashboard.logit.io).
2. Open the stack **Settings** page (Overview).
3. In **Access**, find **OpenSearch MCP**.
4. Select **Enable**.

Logit.io provisions `{stack-id}-mcp.logit.io` and generates a dedicated MCP API key.

For **Personal MCP access** on Small Team, Business or Custom:

1. As a stack administrator, enable **OpenSearch API (user credentials)** under **Settings → Access**.
2. With **OpenSearch MCP** enabled, enable **Personal MCP access** on the same stack.

Logit.io provisions `https://{stack-id}-mcp-user.logit.io/mcp`. Personal MCP uses your OpenSearch API username (your Logit user ID) and password from **Profile settings**. It follows your Teams and custom OpenSearch roles, so queries can only read data those roles allow. See [OpenSearch API (user credentials)](/opensearch-api/user-credentials) to create or rotate your login.

For CI and agents, use a service account (`svc-{id}`) from **Account Settings → OpenSearch API (user credentials)**. Its assigned role and stack scope apply to Personal MCP too.

New stacks have MCP enabled on all plans. Small Team, Business and Custom stacks, including active trials on those plans, also start with user credentials and Personal MCP enabled, and an OpenSearch API login is created for the stack creator. Personal MCP is off on existing stacks until an administrator enables it.

Disable from the same **Access** card. Turning off MCP or OpenSearch API user credentials also turns off Personal MCP. Enable access separately on each stack you want clients to reach.

### 2. Connect with Personal MCP

Use the same username and password as the OpenSearch API user endpoint. Set the `Authorization` header to `Basic ` followed by the Base64 encoding of `username:password`:

```json
{
  "mcpServers": {
    "logit-opensearch-personal": {
      "url": "https://{stack-id}-mcp-user.logit.io/mcp",
      "headers": {
        "Authorization": "Basic <base64-of-username:password>"
      }
    }
  }
}
```

Replace the stack ID and encoded credentials before saving. Rotating or disabling your OpenSearch API login affects both REST API access and Personal MCP. Rotate or revoke service-account credentials when an agent or pipeline no longer needs access.

### 3. Copy stack connection details (administrators)

Stack administrators can open **Settings → Endpoints**. The **OpenSearch MCP (read-only)** section shows:

| Field | Value |
| --- | --- |
| **MCP URL** | `@mcp.endpointAddress` |
| **Username** | `@mcp.username` |
| **Password for Basic auth** | Dedicated MCP key, separate from the OpenSearch `-es` key; `@mcp.apiKey` when signed in |
| **Example config** | JSON ready to paste into your MCP client (for example Cursor or Claude Desktop) |

Rotate the MCP API key from the Endpoints page when you need to invalidate a previous key. Do **not** reuse your OpenSearch `-es` stack API key for MCP.

### 4. Example: connect Cursor

1. Use the Personal MCP config above, or, as a stack administrator, copy the stack config from **Settings → Endpoints** or the auto-filled example below.
2. In Cursor, open **Settings → MCP** (or edit your MCP config file, for example `.cursor/mcp.json`).
3. Add a server entry, or merge the `logit-opensearch` block into an existing `mcpServers` object.
4. Save, then confirm the server connects and tools are listed.

```json copy /@mcp.endpointAddress/ /@mcp.base64encodedAuthString/
{
  "mcpServers": {
    "logit-opensearch": {
      "url": "@mcp.endpointAddress",
      "headers": {
        "Authorization": "Basic @mcp.base64encodedAuthString"
      }
    }
  }
}
```

The Endpoints page also provides a ready-to-copy block with the correctly encoded `Authorization` header. Prefer that over encoding credentials by hand.

### 5. Example: connect Claude Desktop

Claude Desktop uses the same JSON shape. Paste your Personal MCP config or the administrator's stack config into Claude's MCP server settings, then restart Claude Desktop if your client version requires it. Confirm the Logit.io server appears and tools are listed.

If your Claude build does not support remote HTTPS MCP with custom headers yet, check Claude's MCP docs for the transport your version supports, or use another MCP-compatible client.

**Other clients:** any MCP client that supports remote MCP over HTTPS with custom headers can use the same URL and Basic credentials.

### 6. First successful query

Once tools are listed:

1. Ask the client to list indexes on the connected stack.
2. Pick an index name from the response.
3. Ask it to search that index for something you expect in the data — for example a recent `timeout`, `5xx`, or service name.

You should see tool calls against the stack and either matching hits or an empty result set. Either way, the connection is working.

Hosted MCP is **read-only**. Write tools are not available. For writes and admin automation, use the [OpenSearch REST API](/opensearch-api/connect) or the [Developer API](/developer-api/getting-started).

### Rate limits

| Plan | Personal MCP (per user) | Stack MCP (per stack key) |
| --- | --- | --- |
| Individual / Development | Not offered | 60/min, 600/hour |
| Small Team | 30/min, 500/hour | 120/min, 2000/hour |
| Business, Custom, any active trial | 120/min, 3000/hour | 1200/min, no hourly cap |

Any active trial uses the trial limits above; Personal MCP is still not offered on Individual or Development. Limits apply separately to each endpoint. When a limit is reached, MCP returns **429 Too Many Requests** with a **Retry-After** header. Wait for the indicated time before retrying. Logit administrators can override limits per stack; customers can view their limits but cannot change them.

### Limitations

| Topic | Behaviour |
| --- | --- |
| **Write operations** | Not available — MCP is always read-only |
| **Credentials** | Basic auth: Profile or service-account login for Personal MCP; dedicated `{stack-id}-mcp` username and MCP key for stack MCP |
| **Plan** | All plans; Individual / Development use stack MCP only |
| **Stack types** | OpenSearch stacks and Logs stacks running an OpenSearch version only |
| **Scope** | Enable each endpoint per stack; Personal MCP follows Teams, custom roles and service-account scope |

### Troubleshooting

| Symptom | What to check |
| --- | --- |
| **401 Unauthorized** | Check the Basic header. Personal MCP needs the current Profile or service-account login; stack MCP needs the dedicated MCP credentials from Endpoints. Has the password or key been rotated or disabled? |
| **403 Forbidden** | For Personal MCP, check your Teams and custom OpenSearch roles, or the service account's assigned role and stack scope. |
| **429 Too Many Requests** | Wait for the time in `Retry-After`, then retry. Check the limits for your plan and endpoint above. |
| **404 / connection failed** | Is the chosen MCP endpoint enabled on this stack? Personal MCP needs both MCP and user credentials enabled. Check the full URL, including `/mcp`. DNS may take a short time after enable. |
| **Client cannot list tools** | Confirm the client supports remote MCP over HTTPS with custom headers; re-paste the dashboard config; restart the client after saving. |
| **Tools listed but queries fail** | Confirm the stack has indexes and data; list indexes first, then search a known index name. |
| **Expected write tool missing** | By design — hosted MCP does not expose write tools. |
| **Docs still show placeholders** | Stack examples require administrator access and a stack with MCP enabled. Other users should use Personal MCP with their Profile credentials. |
